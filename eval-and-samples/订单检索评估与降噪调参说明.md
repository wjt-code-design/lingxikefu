## 3. 指标定义

- **recall@k（召回正确率）** = 检索返回的 k 条中，属于"相关文档"的数量 ÷ 该查询标注的相关文档总数
- **precision@k（召回精确率）** = 检索返回的 k 条中，属于"相关文档"的数量 ÷ k
- **hit@1** = 检索第一条是否命中相关文档（二值，用于看"答对第一位"的可观感）

> 判定"相关"用人工 golden（见 §4），口径偏严格：每个查询只标 1~2 份精确相关文档，top-k 里其余"售后近义但仍不相关"的文档都计为不相关。因此 precision@k 是上界偏低的保守值，实际可用性可结合 hit@1 与 recall 综合看。

## 5. 复现方法

前提：后端容器已起（postgres/redis/qdrant + api），且订单 demo 数据已导入（见下）。

```bash
# 1) 确保订单 demo 数据在 KB（幂等）：
docker compose exec -T api python scripts/seed_demo_data.py
# 会创建 demo KB（若空）并把 kb 下文档导入 + 向量化

# 2) 重跑评估（容器内，依赖 app 代码 + Qdrant）：
docker compose exec -T api python - <<'PY'
# （若你的 shell 不支持 heredoc，把下方内容存为临时 .py 再 docker cp 进容器执行）
import sys, uuid
from sqlalchemy import select
from app.core.database import SessionLocal
from app.models.knowledge import Document
from app.services.retrieval_service import search_kb
KB = uuid.UUID("f3d26c91-cb3e-42b6-8f19-9610e662976e")
GOLDEN = [("七天无理由退货怎么申请",["退换货政策","常见问题FAQ"]),("退款多久能到账，原路退回吗",["支付与退款","退换货政策"]),("我的快递到哪了，查一下物流",["模拟订单-物流轨迹","发货与时效"]),("订单已经发货了，能改收货地址到上海浦东吗",["模拟订单-改地址与物流催办","模拟订单-配送签收说明"]),("订单尾号8823买的洗衣机，显示已签收但我没收到",["模拟订单-综合售后案例"]),("快递三天没更新了，帮我催一下",["模拟订单-改地址与物流催办","发货与时效"]),("帮我查一下订单999999在不在",["模拟订单-改地址与物流催办"]),("手机保修期是多久",["商品保修条款","延保与碎屏险服务协议"]),("大件家电怎么预约送装",["模拟订单-送装预约","大家电送装与安装说明"]),("买家电开发票税率多少",["发票政策"])]
db = SessionLocal()
names = {d.name: str(d.id) for d in db.scalars(select(Document).where(Document.kb_id == KB, Document.status=="indexed")).all()}
db.close()
def res(p): return [did for n,did in names.items() if n.startswith(p)]
ps=rs=h1=0
for q,rels in GOLDEN:
    rel=[d for pr in rels for d in res(pr)]
    cs=search_kb(q, KB, top_k=5)
    hit=set(c.doc_id for c in cs)&set(rel)
    ps+=len(hit)/5; rs+=len(hit)/len(rel); h1+= 1 if (cs and cs[0].doc_id in rel) else 0
n=len(GOLDEN)
print(f"precision@5={ps/n:.2%}  recall@5={rs/n:.2%}  hit@1={h1}/{n}")
PY
```

## 6. 参数扫描依据（2026-08-21，同 golden 真检索）

| top_k | min_score | precision@5 | recall@5 | hit@1 | 结论 |
|---|---|---|---|---|---|
| **8（改前生产）** | 0.30 | 20% | 95% | 8/10 | 基线 |
| **5（落地）** | 0.30 | **32%** | 95% | 8/10 | 选此：precision +12pt、recall 无损 |
| 5 | 0.50 | 43% | **75%** | 8/10 | pinch 更高但 recall 破线 |
| 5 | 0.55 | 53% | **50%** | 7/10 | recall 崩，不可取 |

**结论**：`top_k` 8→5 是纯收益（低分近义文档只稀释上下文）；靠抬 `MIN_SCORE` 换 precision 会伤 recall（0.50 后破 85% 线），故阈值保守保留 0.30。

## 8. 诚实边界

- golden 为人工语义标注（10 条），非产品冻结集；指标做**方向性诊断与回归**，不当权威 benchmark。
- 数据是**演示/模拟**场景（订单/物流均标注演示），真实生产数据需另立 golden。
- precision@k 口径严格（单标 1~2 份精确相关），绝对数值天然偏低；横向对比同一 golden 的变化趋势更有意义。

## 9. 2026-08-21 后续决策纪要

**检索降噪（已落地）**
- `RETRIEVAL_TOP_K` 8→5：precision@5 20%→32%（纯收益），recall@5 不变（95%）；注释含扫描依据。
- `MIN_SCORE` 0.30 兼作 **context 硬过滤**：低于阈值的低分近义片段不进 prompt；拒答判定用原始 best_dense，解耦。
- `run_pipeline` / `stream_answer` 的 `top_k` 默认改为跟随 `settings.RETRIEVAL_TOP_K`（此前 chat 未接线，改 config 不生效——修复点）。

**已回退的实验（均实测无效，勿再走）**
- 跨文档多样性截断：precision 仍 32%（诊断显示霸双槽的本来就是相关文档，截断无益）。
- 模拟订单去模板头：precision 30%（降）+ recall 降 5pt（模板行的"场景描述"本有区分度）。

**rerank 决策**
- 依赖当前不可用：百炼 `gte-rerank-v2` 实测 HTTP 403 `AllocationQuota.FreeTierOnly`（免费额度耗尽，需充值）。
- 结论：当前**不建议开**（recall 95% / hit@1 80% 已达标，precision 低是口径+同域数据属性）。
- 触发线：正式上线 + 知识库放大后，若 `hit@1` 下滑或出现**串答**再上；届时先实现 rerank client + 充值。

**答案缓存（TTL 24→72h）**
- 命中 TTFT ≈ 0.02s vs 未命中 ≈ 9s（实测 12 条高频）。
- **cache put 无 bug**：隔离诊断（假/真实 kb put→get 均 HIT；真实端到端 HIT；rewrite-history 不改 key）。
- 最初"两轮 miss"主因是缓存 24h 过期/未建立（冷态），非故障 → 真正杠杆是 **TTL + 预热**（预热脚本幂等：先 get 命中即跳过）。

**QA 抽检（19 条真实）**
- 0 条幻觉性错误；正常答上 14/19（73.7%）、诚实拒答/正确转人 5/19（26.3%）。
- 唯一知识缺口：#12 改登录密码无资料（应补常见问题），非检索/幻觉问题。

**顾客端来源可见性**

## 10. 2026-08-21 RRF 权重 / MIN_SCORE 参数扫描（本轮，实测无收益不采纳）

> 脚本：`eval-and-samples/sweep_rrf.py`（评估用，不改生产代码）。容器内真检索，82 题 × 原始双路 hits，
> 权重只影响排序合成，一次取向量全网格命中复用。**口径诚实：评测库每问仅 1 个期望来源、无逐题负样本，
> 故 precision@5 测不准，用 recall@5 + hit@1 + 区分度作代理（与 run_eval 同口径）。**

- **RRF 权重扫描**（w_dense × w_sparse ∈ 8 组）：**recall@5 恒 95.1%（固定 4 题真召不回，非参数可救）；
  hit@1 基线 2.0/1.0 = 72.0% 为最高档之一（唯一并列 1.0/0.5=72.0%，其余全部更低）**。
  → 无任何组合超过基线，**不调整**（当前 2.0/1.0 已是局部最优）。
- **MIN_SCORE 过滤影响**（期望来源被误删比例）：0.30→**0.0%**、0.35→2.4%、0.40→**12.2%**、0.45→25.6%。
  → **0.30 已是拐点，提升会显著伤 recall（0.40 损失 12%）**，**不调**。
- **区分度**：可答题 top1 dense 均值 0.502、中位 0.490、全部 ≥0.30 → MIN_SCORE=0.30 有安全垫，是合理拒答阈值。
- **结论：维持现状（w_dense=2.0/w_sparse=1.0、RETRIEVAL_TOP_K=5、MIN_SCORE=0.30）。
  本轮用实测关掉了"再调调看"的冲动，避免重蹈多样性/模板移除的无价值实验。**
